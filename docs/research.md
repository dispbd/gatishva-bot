# Исследование: готовые боты, источники данных, задержки

Октябрь 2026. Всё, что ниже названо «измерено», получено запросами к живым источникам
7–8 октября 2026; сохранённые ответы лежат в [test/fixtures](../test/fixtures).

## 1. Есть ли готовое решение

| Бот / сервис | Вода | Свет Тбилиси (Telasi) | Газ Тбилиси (Tbilisi Energy) | Регионы | Подписка на улицу | Улица выделена | Состояние |
|---|---|---|---|---|---|---|---|
| @tbilisi_outages_bot | GWP | да | нет | нет | да | **да** | мёртв с февраля 2024 |
| @wutbi_bot (Watt's Up Tbilisi) | GWP | да | нет | нет | да | нет | работает, исходников нет |
| @WaterGeorgia_bot + water.andreev-e.ru | GWP, water.gov.ge | **нет** | **нет** | Energo-Pro, SOCAR | нет (только на сайте) | нет | работает |
| mapi.ge (+ @mapi_ge) | GWP, Батуми | **нет** | **нет** («планируем») | Energo-Pro, SOCAR | да | нет | работает, обновление ~раз в 30 мин |
| канал WETbilisi | | | | | по районам | нет | канал, не бот |

Ни один не закрывает Тбилиси целиком (вода + Telasi + газ Tbilisi Energy) вместе с подпиской
на улицу и выделением. Поэтому — свой бот.

Что удалось выяснить про конкретных конкурентов:

- **@tbilisi_outages_bot** — судя по формату сообщений («💧 Water 💧», улица жирным,
  английский текст), это открытый проект
  [roaddust2/outages-ge-bot](https://github.com/roaddust2/outages-ge-bot), архивированный
  25.04.2024. Он парсил HTML-таблицы gwp.ge и telasi.ge, рассылал **каждые 30 минут и только
  с 08:00 до 18:00** (`CronTrigger "0,30 8-17 * * *"` в `app/main.py`), умел максимум 2 адреса.
  Сайты GWP и Telasi с тех пор переписаны на SPA (Angular и Nuxt) — старые HTML-таблицы
  исчезли, и парсер умер вместе с ними.
- **@WaterGeorgia_bot** — исходники открыты: [andreev-e/water_ge](https://github.com/andreev-e/water_ge)
  (Laravel, ветка `master`). Опрос GWP, water.gov.ge, Energo-Pro и SOCAR **каждые 5 минут**
  (`app/Console/Kernel.php`); перевод текстов отдельной задачей **раз в час** через LingvaNex.
  Telasi и Tbilisi Energy не подключены вовсе — для Тбилиси у него есть только вода.
- **@wutbi_bot** берёт заметки Telasi: его сообщение «Emergency works from 1 Oct 20:28 due to
  1 Oct 20:32» в точности совпадает с заметкой Telasi №5899, созданной в 20:28:01 с прогнозом
  20:32, а пришло оно в 20:30. Заметка №5898 создана в 20:10:35, пришла в 20:17. То есть бот опрашивает
  раз в несколько минут, и время в его сообщении — это время **публикации**, а не отключения.

## 2. Откуда брать данные

У пяти из шести поставщиков есть JSON API — тот самый, из которого рисуют их собственные
сайты. Ключей не нужно; сторонние агрегаторы не нужны и только добавили бы задержку.

| Поставщик | Что | Запрос | Размер | Ответ | Особенности |
|---|---|---|---|---|---|
| **GWP** | вода, Тбилиси | `GET https://www.gwp.ge/api/Disconnect` (текущие) и `/api/Disconnect/ListPlanAsync` (плановые) | 2–4 КБ | ~80 мс | Структурные поля дат пустые (`0001-01-01`), даты — в тексте `emailText`, формат **М/Д/ГГГГ**. Отключение **исчезает из списка, когда вода дана** — это сигнал «завершено». |
| **Telasi** | свет, Тбилиси | `POST https://app.telasi.ge/api/view/telasi/getPoweroutages`, заголовок `lang: ka`, тело `{"contentType":"poweroutage","searchText":"","perPage":8}` | 73 КБ (30 заметок по умолчанию — 250 КБ) | ~250 мс | Два списка: `content` — заметки, которые сотрудники пишут руками (HTML), и `api` — структурный список текущих отключений (`code`, `outage_time`, `poweron_time`), который при всех проверках был пуст. **Полон только грузинский**: русский содержит лишь плановые работы, английский почти пуст. Текст «грязный»: слова разорваны пробелами и `<span>`-ами («ბუაჩი ძის», «04: 10»). |
| **Tbilisi Energy** | газ, Тбилиси | HTML: `https://te.ge/ka/117/blog/emergency-shutdown.html` → ссылки на свежие посты → сами посты | ~30 КБ на страницу | ~400 мс | API нет. CloudFront отвечает **403 без браузерного User-Agent**. Постов — единицы в месяц, времена — в прозе («29 სექტემბრის 11:30 სთ-დან…»), счётчик просмотров меняет страницу при каждом запросе. |
| **Energo-Pro** | свет, регионы | `POST https://my.energo-pro.ge/owback/searchAlerts`, тело `{"search":""}` | 64 КБ, ~100 записей | ~120 мс | Явные «с/до», `taskType "1"` = плановое, адреса путём «район/село/улица». |
| **SOCAR Georgia Gas** | газ, регионы | `GET https://utilixwebapi.azurewebsites.net/api/Outage/GetOutagesWithPaging?pageIndex=1&PageSize=50`, `Referer: https://www.mygas.ge/` | 108 КБ | ~0,7–1,4 с | ISO-времена, время создания, **официальный английский перевод** каждого уведомления. |
| **UWSC** (water.gov.ge) | вода, регионы | `GET https://water.gov.ge/api/v1/site/planned-works?date_from=ГГГГ-ММ-ДД&page_size=100` | 16 КБ за сутки (без фильтра — 1 МБ) | ~150 мс | Город — в заголовке, адреса — массивом. |

**Сколько это стоит.** Опрос раз в минуту для Тбилиси и раз в 2–10 минут для остального —
около 5 000 запросов в сутки ко всем поставщикам вместе. Разбор одного изменившегося ответа —
от 0,3 мс (GWP) до ~5 мс (Energo-Pro, Telasi) на Node; неизменившийся ответ узнаётся по
SHA-256 и не разбирается вовсе. Это укладывается в бесплатный тариф Cloudflare Workers
(10 мс CPU на запуск, 50 подзапросов, 100 000 запросов в сутки) с запасом.

### GWP доступен не отовсюду

Выяснилось уже после деплоя: **gwp.ge отвечает только из Грузии и из Мадрида.**

| Откуда | Результат |
|---|---|
| 40 узлов check-host.net (Европа, США, Азия, Израиль, Турция, Россия, Иран…) | таймаут везде, кроме одного узла в Мадриде (Барселона — таймаут) |
| Cloudflare: FRA, MXP, AMS, LHR, LIS, MRS, CDG, EWR, MIA, SJC, SIN | таймаут |
| Cloudflare: MAD | 200 за 0,3–0,4 с, каждый раз |
| Cloudflare: TBS (Тбилиси) | 200 за ~10–80 мс |
| AWS через Vercel: fra1, iad1, arn1, cdg1 | таймаут |

Пробовали и не подошло:
- прокси на Vercel — AWS тоже заблокирован;
- placement hint (`hostname = "www.gwp.ge"`) — Worker исполнялся там, куда пришёл запрос
  (MXP), а не в Тбилиси;
- `api.gwp.ge` — HTTPS не отвечает;
- бесплатного VPS в Грузии найти не удалось (местные хостеры — от ~40 ₾ в месяц).

Сработало: Durable Object, созданный с подсказкой `weur`, в ~⅓ случаев оказывается в
Мадриде и там остаётся. Бот находит такой сам и меняет его, если тот перестал работать.
У water.andreev-e.ru (сервер в Эстонии) GWP на момент проверки «обновлялся 8 часов назад» —
похоже, они упираются в ту же стену.

## 3. Откуда задержки

Путь события: **отключение → поставщик публикует → бот замечает → бот обрабатывает →
Telegram доставляет.** Каждый этап можно оценить отдельно.

### Поставщик публикует поздно — главная причина для света

Заметка Telasi об аварии содержит время публикации и прогноз восстановления. Для 18 аварийных
заметок за 26 сентября – 7 октября:

| Публикация | Прогноз восстановления | Прогноз − публикация | Причина |
|---|---|---|---|
| 07.10 17:54 | 07.10 17:47 | **−7 мин** | переключение |
| 07.10 13:31 | 07.10 13:38 | +7 мин | переключение |
| 07.10 11:23 | 07.10 11:29 | +6 мин | переключение |
| 07.10 07:35 | 07.10 06:20 | **−76 мин** | пожар |
| 07.10 00:13 | 07.10 00:22 | +9 мин | авария |
| 06.10 07:58 | 06.10 07:49 | **−10 мин** | авария |
| 05.10 01:33 | 05.10 01:31 | **−2 мин** | переключение |
| 01.10 20:10 | 01.10 20:10 | **−1 мин** | переключение |
| 28.09 02:32 | 28.09 01:39 | **−54 мин** | переключение |
| … ещё 9 | | | |

- в **6 из 18** случаев к моменту публикации прогноз восстановления **уже прошёл**;
- ещё в **7** до него оставалось ≤ 15 минут; медиана — **5 минут**.

То есть Telasi пишет заметку, когда свет уже дали или вот-вот дадут. Переключения длятся
5–15 минут, и никакой бот не может сообщить о них раньше, чем Telasi их опубликует. Отсюда
и «свет уже включили, а бот только прислал». Бот в таких случаях честно пишет
«Восстановление ожидалось к 17:47 — раньше, чем вышло сообщение».

У GWP, SOCAR и UWSC такой проблемы почти нет: плановые работы публикуются за 1–2 суток,
аварии по воде длятся часами.

### Бот опрашивает редко — вторая причина

| Бот | Период опроса |
|---|---|
| @tbilisi_outages_bot | 30 мин, только 08:00–18:00 |
| mapi.ge | ~30 мин (по их собственным словам) |
| @WaterGeorgia_bot | 5 мин (+ перевод раз в час) |
| @wutbi_bot | по наблюдению — 2–7 мин |
| **Gatishva** | **60 с** для GWP и Telasi; 2–10 мин для остального |

### Обработка и доставка — не причина

Источники отвечают за 0,1–1,5 с, разбор — миллисекунды. Telegram допускает ~30 сообщений в
секунду в разные чаты: тысяча подписчиков одной улицы получит сообщение примерно за 35 секунд.
Бот отправляет пачками по 30 и перезапускает себя через секунду, а на ответ 429 ждёт ровно
столько, сколько попросил Telegram.

### Насколько быстро можно

**Задержка ≈ задержка публикации у поставщика + до 60 секунд.** Период можно сократить до
20–30 секунд (будильник Durable Object это позволяет, ответы GWP и Telasi маленькие), но для
света это почти ничего не даст — минуты теряются у Telasi. Быстрее мог бы быть только
структурный список `api` у Telasi, если он заполняется из диспетчерской системы раньше
ручной заметки: бот его уже читает, но пустым он был при всех проверках, так что подтвердить
это пока нечем.

Бот сам собирает эту статистику: `/status` показывает медиану «опубликовано → увидели» по
каждому источнику за неделю. Фоновый замер во время исследования (опрос всех источников раз в
минуту, ночь на 8 октября) новых событий не застал — ночью их почти нет.

## 4. Решения, которые из этого следуют

- **Прямые API поставщиков, без агрегаторов** и без перевода через сторонний сервис.
- **Грузинский как источник истины.** Подписка «Политковская» / «Politkovskaya» /
  «პოლიტკოვსკაია» сравнивается с грузинским текстом через общий фонетический «скелет», с
  поправкой на падежные окончания и разорванные слова.
- **Не машинный перевод, а транслитерация** улиц плюс словарь типов («ქ.» → «ул.»,
  «შესახვევი» → «пер.»): ваша улица остаётся узнаваемой.
- **Раскрывающиеся цитаты** (`<blockquote expandable>`) для длинного списка адресов
  (бывает 135 улиц в одной заметке) и для оригинала; ваша улица — жирным и в шапке, и внутри.
- **«Завершено»** — там, где поставщик это сообщает (исчезновение из списка текущих у GWP).

## 5. Чего пока нет

- Номера домов не учитываются: подписка на улицу срабатывает и на «N32-50 (чётные)», и на
  нечётную сторону.
- Структура живого списка Telasi (`api`) взята из JavaScript их сайта и не проверена на
  реальных данных.
- Tbilisi Energy не даёт списка адресов — сопоставление идёт по всему тексту поста.
- Транслитерация русских названий приблизительна («Пшавела», но и «Митропане» вместо
  «Митрофане»: ფ в фамилиях по-русски обычно «п», в именах — «ф»).
- Батуми-вода (Batumis Tskali) не подключена.
