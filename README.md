# Gatishva — отключения воды, света и газа в Грузии

*გათიშვა* (gatishva) — по-грузински «отключение». Telegram-бот, который присылает
отключения **по вашей улице**, выделяет её жирным и прячет длинный список адресов под
раскрывающийся спойлер. Работает в личке, в группах и в каналах.

Почему не взять готовый бот и откуда берутся данные — в [docs/research.md](docs/research.md).

## Как выглядит сообщение

```
💧 Вода · Тбилиси, Мтацминда
⚠️ Аварийное · повреждение сети
🕒 07.10 15:00 – 08.10 03:00
📍 Зураб Жвания                         ← ваша улица, жирным, по-русски
▸ 📋 Адреса (7): Митропане Лагидзе, …, Зураб Жвания, …     ← раскрывается
▸ 🇬🇪 მთაწმინდა, ალექსანდრე ჭავჭავაძის ქ. … ჟვანიას …     ← оригинал, улица жирным
GWP · опубликовано …
```

Когда поставщик убирает отключение из списка текущих (GWP, «живой» список Telasi),
сообщение редактируется и приходит тихий ответ «✅ отключение завершено».

## Команды

| Команда | Что делает |
|---|---|
| `/add Политковская` | улица в Тбилиси — по-русски, латиницей или по-грузински |
| `/add Политковская, Мтацминда` | улица и её район — для аварий на весь район, если бот ещё не видел улицу |
| `/add Батуми, Руставели` | улица в другом городе |
| `/city Кутаиси` | весь город |
| `/road Гудаури` | перекрытия и восстановление движения на дорогах, где упоминается это место |
| `/list` | подписки, удаление кнопкой |
| `/types` | что присылать: 💧 / 💡 / 🔥 |
| `/now` | что отключено прямо сейчас по вашим адресам |
| `/lang` | язык чата: русский, English, ქართული |
| `/status` | только для `TELEGRAM_ALERT_CHAT_ID`: состояние источников и задержки |

В личке можно просто написать название улицы. В группе бот работает с включённым
privacy mode: он видит только команды и ответы на свои сообщения, поэтому кнопка
«📍 Добавить улицу» присылает force-reply. Менять подписки группы могут только админы.

## Источники

| Источник | Что | Как | Период опроса |
|---|---|---|---|
| GWP | вода, Тбилиси | JSON `gwp.ge/api/Disconnect` | 60 с |
| Telasi | свет, Тбилиси | JSON `app.telasi.ge/api/view/telasi/getPoweroutages` | 60 с |
| Tbilisi Energy | газ, Тбилиси | HTML блога `te.ge` | 10 мин |
| Energo-Pro | свет, регионы | JSON `my.energo-pro.ge/owback/searchAlerts` | 2 мин |
| SOCAR Georgia Gas | газ, регионы | JSON API за `mygas.ge` | 5 мин |
| UWSC | вода, регионы | JSON `water.gov.ge/api/v1/site/planned-works` | 5 мин |
| NEA (meteo.gov.ge) | опасная погода, по муниципалитетам | JSON `meteo.gov.ge/Ge/Warnings/GetMap`; 11 МБ, почти всё — контуры муниципалитетов, вырезаются сразу | 1 ч |
| Департамент автодорог | перекрытия дорог | данные Next.js-страницы `georoad.gov.ge/ka/restriction` (`parsedData`): статус 1 — ограничено, 2 — восстановлено | 5 мин |

`npm run probe` опрашивает все источники один раз и показывает, что пришло, — первое, что
стоит запустить, когда бот пишет «источник не отвечает».

### GWP — через ретранслятор в Мадриде

gwp.ge отвечает только из Грузии — и, как выяснилось, из Мадрида. Измерено 08.10.2026:
с 40 узлов check-host.net по всему миру ответил один мадридский; из Cloudflare — таймауты во
Франкфурте, Милане, Амстердаме, Лондоне, Лиссабоне, Нью-Йорке, Майами, Сан-Хосе и Сингапуре,
а мадридский дата-центр Cloudflare отвечал каждый раз за 0,3–0,4 с. AWS (через Vercel)
не пускается ни в одном регионе; placement hint не переносит Worker в Тбилиси.

Durable Object нельзя переселить, но новый можно *создать* с подсказкой региона, и он
останется там, где создан. С подсказкой `weur` примерно каждый третий попадает в Мадрид.
Поэтому Hub создаёт по 4 ретранслятора ([src/gwp-relay-do.ts](src/gwp-relay-do.ts)), пока
один не достучится до GWP, запоминает его и ищет новый только после 3 неудач подряд.
Ретранслятор ничего не хранит, так что брошенные кандидаты ничего не стоят. Где он сейчас —
первая строка `/status`.

Это наблюдение, а не гарантия: если GWP перестанет пускать Мадрид, поиск будет
безуспешным, источник `gwp` начнёт падать и бот пришлёт алерт.

Без ретранслятора (`npm run probe` на машине в Грузии) запрос идёт напрямую.

## Как устроено

```
cron */5 ──► ensureAlarm ─┐
                          ▼
             ┌──────── Hub (Durable Object, SQLite) ────────┐
 alarm ────► │ poll due sources → hash → parse → diff        │
             │   new / changed / vanished → outbox           │
             │ drain outbox (≤5 messages per run)            │──► Telegram
             │ re-arm: next source due, or +1 s if outbox    │
             └───────────────────────────────────────────────┘
Telegram webhook ──► Worker /tg ──► bot.ts ──► Hub RPC (subscribe, list, …)
```

- **Сопоставление улиц** ([src/georgian.ts](src/georgian.ts)). И текст поставщика, и то, что
  ввёл человек, сводятся к «скелету» — грубой латинице, где неразличимые для русского уха
  буквы совпадают (კ/ქ/ყ → k, ჭ/ჩ → ch, ц/წ/ც → c). Пробелы выбрасываются, поэтому
  совпадение переживает «рваные» слова в текстах Telasi («ბუაჩი ძის»). Совпадение должно
  начинаться с начала слова, у запроса отрезается конечная гласная — грузинский меняет
  окончание по падежу (ჭავჭავაძე → ჭავჭავაძის).
- **Перевод** не машинный: улицы — имена собственные, их транслитерируют
  ([`addressLocal`](src/georgian.ts)) и ставят в именительный падеж, а тип улицы переводят по
  словарю. Оригинал целиком — во втором спойлере.
- **Три языка: русский, английский, грузинский** ([src/i18n.ts](src/i18n.ts)). Язык
  принадлежит чату, а не человеку: группа читает на одном. Новый чат берёт язык Telegram
  первого пользователя (ru/uk/be… → русский, ka → грузинский, остальное → английский),
  `/lang` меняет его. На русском и английском — шапка, адреса и интерфейс на языке чата плюс
  грузинский оригинал; английские названия — официальной латиницей, как на табличках
  (Chavchavadze, Tsereteli, Qazbegi). На грузинском перевод совпал бы с оригиналом, поэтому
  после шапки идёт только оригинал, без отдельного списка адресов.
- **Первое чтение источника ничего не рассылает** — иначе весь архив Telasi пришёл бы разом.
- **Неизменившийся ответ не разбирается**: его SHA-256 совпадает с прошлым, и опрос стоит
  долю миллисекунды CPU.
- **Аварии на весь район.** Иногда поставщик называет только районы, без улиц: 8 октября
  Telasi написал «не подаётся в районы Сололаки-Мтацминда-Крцаниси и Исани». Сопоставлять
  такую заметку с улицей не по чему, поэтому бот запоминает район каждой подписанной улицы:
  GWP и плановые заметки Telasi перечисляют улицы под названием района. Такое сообщение
  начинается строкой «📍 Отключение на весь район, в том числе …». Пока улица не встречалась
  ни в одном отключении, её район можно указать вручную.
- **Новая подписка сразу присылает текущие отключения** по ней и показывает, как улица уже
  встречалась в данных, — сразу видно, что запрос понят.

### Бесплатный тариф Cloudflare

| Лимит | Free | Расход |
|---|---|---|
| Запросов к Worker/DO в сутки | 100 000 | ~3 000 будильников + вебхуки |
| Подзапросов за один запуск | 50 | ≤ 10 на опрос + ≤ 5 на отправку |
| CPU на запуск | 10 мс | разбор изменившегося ответа ≤ 5 мс, неизменившегося ~0; сообщение 2–3 мс, поэтому по 5 за запуск |
| Cron-триггеров | 5 на аккаунт | 1 |

Telasi по умолчанию отдаёт 30 заметок (~250 КБ, ~7 мс разбора) — запрашиваются 8 (`perPage`).

## Развёртывание

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`, например `@gatishva_bot`) и
   впишите имя в `BOT_USERNAME` в [wrangler.toml](wrangler.toml). Privacy mode оставьте включённым.
2. ```bash
   npm install
   npx wrangler secret put TELEGRAM_BOT_TOKEN
   npx wrangler secret put TG_WEBHOOK_SECRET        # любая длинная случайная строка
   npx wrangler secret put TELEGRAM_ALERT_CHAT_ID   # ваш Telegram id — алерты и /status
   npm run deploy
   ```
3. Откройте `https://gatishva-bot.<subdomain>.workers.dev/health` — это заводит цикл опроса.
4. ```bash
   TG_WEBHOOK_SECRET=<то же значение> npm run setup -- --url https://gatishva-bot.<subdomain>.workers.dev/tg
   ```

Первые минуты бот только запоминает, что уже опубликовано; рассылать он начнёт с первого
нового отключения.

### Автодеплой

Каждый push в `master` деплоится через Cloudflare Workers Builds (Worker → Settings → Build):

| Поле | Значение |
|---|---|
| Repository | `dispbd/gatishva-bot`, ветка `master` |
| Root directory | `/` — проект лежит в корне репозитория |
| Build command | пусто |
| Deploy command | `npm run deploy` — сначала типы и тесты, деплой только если они прошли |

Версию Node сборка берёт из `.node-version` (24): тесты запускают TypeScript напрямую, а
без флагов Node умеет это только с 23-й версии. Секреты живут в Cloudflare и деплоем не
затрагиваются; `[vars]` из `wrangler.toml` при каждом деплое перезаписывают то, что
поменяли в панели вручную.

## Разработка

```bash
npm test          # парсеры на сохранённых ответах источников, сопоставление, рендер
npm run check     # типы + тесты (запускается перед deploy)
npm run probe     # живой опрос всех источников
```

Для `wrangler dev` используйте **отдельного тестового бота**: у локального запуска своё
пустое хранилище, и с боевым токеном он отвечал бы настоящим пользователям.
Кириллицу в тестовые запросы к локальному вебхуку отправляйте из Node, а не `curl` из Git
Bash на Windows — она приходит знаками вопроса.
